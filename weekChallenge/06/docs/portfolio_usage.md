# 포트폴리오 사용 설명서

이 문서는 `index.html` 한 페이지로 구성된 박상욱(Steve Park)의 이력/포트폴리오 사이트를 어떻게 보고, 해석하고, 수정하면 되는지를 정리한 가이드입니다.

## 1. 무엇을 보여주는 사이트인가

- 단일 정적 HTML 페이지(`index.html`)로, 빌드 과정 없이 브라우저에서 바로 열거나 GitHub Pages(`https://1sanguk.github.io/Portfolio/`)로 배포됩니다.
- 구성 순서: **ABOUT ME(헤더) → 학력·교육이수 → 경력사항 → 어학/자격증 → 활용능력 → 프로젝트 목록**.
- 상단 네비게이션(`.topnav`)과 목차 섹션(`.toc`)에 동일한 앵커 링크가 있어, 어디서든 원하는 섹션으로 바로 이동할 수 있습니다.

## 2. 화면 구조와 인터랙션 해석법

| UI 요소 | 동작 | 해석 방법 |
|---|---|---|
| 상단 `mini-toc` | 스크롤 위치에 따라 현재 보고 있는 섹션 링크가 자동으로 강조(`active`) | 페이지 어디에 있는지 알려주는 스크롤스파이입니다. 클릭하면 해당 섹션으로 이동합니다. |
| `h2.toggle` (섹션 제목) | 클릭 시 `section.block`에 `collapsed` 클래스 토글 | 섹션 전체를 접고 펼치는 용도입니다. 처음 진입 시 펼쳐진 상태가 기본값입니다. |
| `.career-timeline-bar` | 회사별 재직 기간을 비율 막대(`width: %`)로 표시, 각 막대에 `title` 툴팁 | 막대 길이 = 재직 기간 비율입니다. 회색(`gap`)으로 표시된 구간은 의도적으로 표기한 **공백기**이며 숨기지 않았습니다. |
| `.proj-item` (프로젝트 카드) | 클릭 시 `open` 클래스 토글로 상세 설명·장르·스크린샷 펼침 | 기본 노출은 직무 요약(`duty` 리스트)과 기술 태그뿐이고, 클릭해야 실제 프로젝트 설명과 이미지가 나옵니다. 즉 카드를 펼치지 않으면 절반의 정보만 보입니다. |
| `.reveal` 클래스가 붙은 섹션 | `IntersectionObserver`로 화면에 12% 이상 들어오면 `in` 클래스 추가(페이드인 효과) | 순수 시각 효과이며 정보와는 무관합니다. |

동작 로직은 `script.js` 한 파일에 들어 있고, 외부 라이브러리 의존성이 없습니다.

## 3. 내용을 해석할 때 참고할 점

- **경력사항의 기간 중복**: 2024.01~2026.02 사이 스카이워크 재직 기간 동안 5개 프로젝트(코코마인, 코코마인 산리오 캐릭터즈, 걸글로브, 유미의 세포들, 놀러와 마이홈)가 동시에 진행되었습니다. 이는 한 프로젝트만 전담한 것이 아니라 **여러 라이브 서비스를 병행 운영**했다는 의미로 읽어야 합니다.
- **공백기 표기**: `career-timeline-bar`에서 회색으로 표시된 2023.01~03, 2023.09~12 구간은 실제 공백기이며, 이력서 상에서 가리지 않고 그대로 노출하는 방식을 택했습니다.
- **단독 개발 vs 협업**: 프로젝트 설명 중 "단독 개발", "PM으로서 총괄"이라고 명시된 항목(삼성 바이오로직스 파트너 포탈, PK Valve PWA, 배러온)은 1인 개발/총괄 프로젝트이고, 나머지는 팀 단위 협업 프로젝트입니다. 구분 표기가 없는 경우 팀 프로젝트로 해석하면 됩니다.
- **기술 태그의 의미**: 각 프로젝트 카드의 태그(`<div class="tags">`)는 해당 프로젝트에서 실제 사용한 기술 스택이며, "활용능력" 섹션의 전체 스킬 목록과 대조하면 어떤 기술을 어떤 프로젝트에서 썼는지 역추적할 수 있습니다.
- **장르 표기**: SI 성격의 공공기관 프로젝트(부산교육청, 강원도교육청, 충청북도교육청 등)는 `proj-genre`가 없고, 게임/커머스 성격 프로젝트만 장르가 별도 표기되어 있습니다.

## 4. 콘텐츠 수정 방법

1. **텍스트 수정**: `index.html` 내 해당 섹션의 `<div class="row">`, `<div class="proj-item">` 블록을 직접 수정합니다. 별도 데이터 파일이나 템플릿 엔진은 사용하지 않습니다(순수 HTML 하드코딩).
2. **새 프로젝트 추가**: 기존 `.proj-item` 블록 하나를 복사해 회사(`.career-job`) 내부에 붙여넣고, 제목/기간/직무 리스트/기술 태그/상세 설명/이미지 경로를 교체합니다.
3. **이미지 추가**: `images/` 폴더에 스크린샷을 추가하고 `<img src="images/파일명.png">` 경로를 맞춰줍니다.
4. **스타일 변경**: 색상, 타이포그래피, 레이아웃은 `style.css`에서 관리합니다(rem 기반 반응형).
5. **인터랙션 변경**: 펼치기/접기, 스크롤스파이 동작은 `script.js`에서 관리합니다.

## 5. 로컬 확인 방법

별도 빌드 없이 `index.html`을 더블클릭해 브라우저로 열면 즉시 확인 가능합니다. 실제 배포본은 GitHub Pages(`https://1sanguk.github.io/Portfolio/`)에서 확인할 수 있습니다.

## 6. 참고: `test/` 폴더

`test/review.json`, `test/review2.json`은 포트폴리오 사이트 자체의 기능이 아니라, 포트폴리오 콘텐츠 품질을 점검하기 위해 별도로 생성한 **가상 리뷰 데이터(연습/검토용 샘플)**입니다. 실제 사용자 후기가 아니며, 사이트 렌더링에는 영향을 주지 않습니다.
